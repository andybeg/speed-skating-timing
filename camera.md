# Камера фото-финиша

Описание выбора, монтажа и программной интеграции камеры для системы хронометража скоростных роликов.

**Связанный документ:** [TZ.md](TZ.md) — общее ТЗ системы. **Функциональное описание:** [functional.md](functional.md)

**Версия:** 0.1  
**Дата:** 2026-05-23  
**Статус:** черновик

---

## 1. Назначение

Камера на **Raspberry Pi 5** фиксирует **фото-финиш** — последовательность кадров в момент пересечения финишной линии. Используется:

- для разрешения спорных финишей (судья сравнивает IR и кадр);
- для привязки кадра к событию `FINISH` через **GPIO trigger** от Finish Unit;
- для просмотра clip в web-UI (прокрутка кадров, overlay линии).

Требования PH-01…PH-09 — в [TZ.md §4.3](TZ.md#43-фото-финиш-на-pi-5).

---

## 2. Место в системе

```
┌─────────────┐   GPIO trigger + UART      ┌──────────────────────────┐
│Finish Unit  │ ──────────────────────────►│   Raspberry Pi 5 8 GB    │
│  ESP32-S3   │                            │   • picamera2 / V4L2     │
└─────────────┘                            │   • ring buffer ≥ 10 с   │
                                           │   • clip ±2 с на SD      │
                                           └────────────┬─────────────┘
                                                        │ CSI или USB
                                           ┌────────────▼─────────────┐
                                           │  Pi Camera Module 3    │
                                           │  (или GS USB — апгрейд)  │
                                           └──────────────────────────┘
```

| Роль | Взаимодействие |
|------|----------------|
| **Finish Unit** | GPIO импульс при `FINISH` → `frame_idx` в ring buffer |
| **Pi 5** | Непрерывный захват 120 fps, сохранение clip по триггеру |
| **Судья** | Просмотр кадров в web-UI, выбор `final_source: line \| photo` |

## 3. Требования (из ТЗ)

| ID | Требование |
|----|------------|
| PH-01 | **RPi 5 8 GB** + **Pi Camera Module 3** (базовая конфигурация) |
| PH-02 | Захват ≥ **120 fps** @ 640×480 (crop/scale из sensor mode) |
| PH-03 | Ring buffer ≥ **10 с** в RAM |
| PH-04 | Триггер: **GPIO** от Finish Unit → `frame_idx` |
| PH-05 | При `FINISH` — clip ±2 с + ключевые кадры на SD |
| PH-06 | Фото-финиш в том же web-UI |
| PH-07 | Overlay: вертикальная линия финиша |
| PH-08 | Камера **строго 90°** к линии; **фиксированный** фокус |
| PH-09 | При расхождении IR и кадра — решение судьи |

**Точность кадра:** ≤ 8 ms @ 120 fps ([TZ.md §5](TZ.md#5-нефункциональные-требования)).

## 4. Рекомендуемая камера (MVP)

### Raspberry Pi Camera Module 3

| Параметр | Значение |
|----------|----------|
| Сенсор | Sony **IMX708**, 12 Мп |
| Режим 120 fps | **1536×864 @ 120** (официальный video mode) |
| Затвор | Rolling shutter |
| Интерфейс | CSI-2 → `picamera2` |
| Объектив | Стандарт **75°** или Wide **120°** |
| Цена (ориентир, РФ) | ~5 740 ₽ (стандарт / NoIR); Wide ~6 450 ₽ |

**Почему Module 3 — основной выбор:**

- Нативная поддержка на Pi 5 (`picamera2`, libcamera).
- Реальный режим **120 fps** без USB-ограничений.
- 640×480 из ТЗ — **crop/scale** из 1536×864, отдельный sensor mode не нужен.
- CSI + GPIO — простейшая синхронизация IR ↔ кадр.

#### Варианты Module 3

| Вариант | Угол (diag.) | Когда брать |
|---------|--------------|-------------|
| **Module 3** | ~75° | Камера близко к линии, 2–4 дорожки в кадре |
| **Module 3 Wide** | ~120° | Дальний монтаж или запас по ширине поля |
| **Module 3 NoIR** | 75° / 120° | ИК-подсветка (ночные/закрытые катки); днём — стандарт с IR-cut |

#### Что не подходит для 120 fps

| Камера | Макс. FPS | Причина |
|--------|-----------|---------|
| Pi Camera Module 2 (IMX219) | 90 @ 640×480 | Не выполняет PH-02 |
| Raspberry Pi GS Camera (IMX296) | 60 @ 1456×1088 | Global shutter, но мало fps |
| ArduCam OV9281 (USB) | 100 @ 1280×800 | Не дотягивает до 120 |

## 5. Альтернативы и апгрейд

### 5.1. Raspberry Pi HQ Camera (CSI)

| Параметр | Значение |
|----------|----------|
| Сенсор | Sony IMX477 |
| 120 fps | **1332×990 @ 120** |
| Затвор | Rolling shutter |
| Минусы | Крупнее, объектив C/CS или M12, ручной фокус, дороже |

Имеет смысл при необходимости **лучшей оптики**. Для типового катка Module 3 проще.

### 5.2. Global Shutter USB (апгрейд)

Если rolling shutter даёт артефакты на быстрых конькобежцах («наклонные» силуэты):

| Модель | FPS | Разрешение | Сенсор | Примечание |
|--------|-----|------------|--------|------------|
| **ArduCam B0385** | **120** MJPEG | 1280×800 | OV9782 color GS | UVC, external trigger; ~$55 |
| **ELP AR0234** | **120** | 1920×1200 | AR0234 color GS | UVC, широкий объектив (~126°) |
| ArduCam B0332 | 100 | 1280×800 | OV9281 mono GS | Не выполняет PH-02 |

**ArduCam B0385 (OV9782)** — предпочтительный GS-апгрейд:

- 120 fps @ 1280×800 (MJPEG).
- External trigger → привязка к GPIO от Finish Unit.
- Минусы: стек **V4L2/OpenCV** (не `picamera2`), нагрузка USB и декод MJPEG, отдельная ветка кода в Pi 5.

Переход на GS USB — **после полевых тестов** Module 3, не в MVP v1.

## 6. Монтаж

| Параметр | Рекомендация |
|----------|--------------|
| Угол | **Строго 90°** к финишной линии (PH-08) |
| Высота | 1–1.5 м, все полосы и белая линия 5 cm в кадре |
| Фокус | После настройки — **manual focus**, AF отключить |
| Подсветка | LED-бар 12 V + рассеиватель ([TZ.md §8.1](TZ.md#81-central-pi-5)) |
| Крепление | Штатив / кронштейн с регулировкой угла |
| Кабель | CSI FPC 15→22 pin, 30–50 cm; не перегибать |

**Проверка перед соревнованием:** тестовый прогон, overlay линии совпадает с физической белой линией.

## 7. Программная конфигурация (Module 3)

### 7.1. Режим захвата

```python
from picamera2 import Picamera2

picam2 = Picamera2()
config = picam2.create_video_configuration(
    main={"size": (1536, 864), "format": "YUV420"},
    controls={"FrameDurationLimits": (8333, 8333)},  # 120 fps
)
picam2.configure(config)
picam2.start()
```

`FrameDurationLimits: (8333, 8333)` — min и max одинаковы → жёсткие 120 fps (~1 000 000 / 120 µs).

### 7.2. Ring buffer и GPIO

| Компонент | Описание |
|-----------|----------|
| Ring buffer | ≥ 10 с кадров в RAM (PH-03); при 120 fps × 1536×864 YUV420 ≈ 300 MB — укладывается в Pi 5 8 GB |
| GPIO trigger | Rising edge от Finish Unit → запись `frame_idx` + timestamp |
| Clip | При `FINISH`: сохранить ±2 с на SD (PH-05) |
| Crop для UI | Отображение 640×480 или полоса вокруг линии — в post-process |

### 7.3. Производительность

- Формат **YUV420** — меньше нагрузка, чем RAW.
- Не печатать в консоль каждый кадр — сильно снижает fps.
- Предпочтительно **NVMe** или быстрый SD A2 для записи clip.
- Мониторинг: `/api/status` → поле `camera_fps` (см. [TZ.md CM-09](TZ.md#45-управление-pi-5-и-задание-heats-смартфон--компьютер)).

### 7.4. GS USB (если апгрейд)

- Захват через **V4L2** (`v4l2-ctl`, OpenCV `VideoCapture`).
- Формат **MJPEG** для 120 fps (YUY2 — ≤ 10 fps на OV9782).
- External trigger: скрипт ArduCam + GPIO (см. [документацию OV9782](https://docs.arducam.com/UVC-Camera/Appilcation-Note/External-Trigger-Mode/OV9782-Global-Shutter/)).

## 10. Риски

| Риск | Митигация |
|------|-----------|
| Rolling shutter искажает силуэт | 120 fps; камера ⊥ линии; при необходимости — GS USB (§5.2) |
| Просадка fps (< 120) | YUV420, без лишнего I/O в цикле; охлаждение Pi 5 |
| Размытый кадр | Manual focus, достаточная подсветка, короткая выдержка |
| Не все полосы в кадре | Module 3 Wide или сдвинуть камеру |
| Перегрев Pi 5 при длительном захвате | Активное охлаждение ([TZ.md §12](TZ.md#12-риски)) |

## 11. Критерии приёмки (камера)

- [ ] Стабильные **≥ 120 fps** не менее 5 мин ([TZ.md §13](TZ.md#13-критерии-приёмки-mvp)).
- [ ] GPIO trigger → `frame_idx` совпадает с кадром пересечения IR (±1 кадр).
- [ ] Clip ±2 с сохраняется на SD при каждом `FINISH`.
- [ ] Overlay линии в UI совпадает с физической финишной линией.
- [ ] Судья открывает фото-финиш в web-UI ≤ 3 с.
