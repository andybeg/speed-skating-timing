# Функциональное описание системы хронометража

Описание системы старта и финиша для **соревнований по скоростным роликам** — что она делает, для кого и как используется на площадке.

**Техническое задание:** [TZ.md](TZ.md)  
**Стартовый модуль (техн.):** [start-unit.md](start-unit.md) · **Камера:** [camera.md](camera.md)

**Версия:** 0.2  
**Дата:** 2026-05-28  
**Статус:** черновик

---

## 1. Назначение

Система автоматизирует **фиксацию старта**, **фиксацию финиша** и **ведение протокола** на соревнованиях по скоростным роликам.

Она нужна организаторам и судейской бригаде, когда:

- несколько участников стартуют одновременно или по очереди;
- важно точно зафиксировать момент пересечения финишной линии;
- возможны плотные финиши, требующие **фото-финиша**;
- протокол должен быть доступен **сразу на площадке** — с телефона или ноутбука, **без интернета**.

---

## 2. Что делает система

| Функция | Описание |
|---------|----------|
| **Старт** | Обратный отсчёт 3–2–1–GO, звук и свет; фиксация момента старта |
| **Финиш** | Автоматическая фиксация пересечения линии по полосам (2–4) |
| **Время** | Расчёт результата заезда от старта до финиша |
| **Live-результаты** | Таблица обновляется на смартфонах и ноутбуках в реальном времени |
| **Фото-финиш** | Сохранение и просмотр кадров при спорных финишах |
| **Протокол** | Формирование и экспорт результатов соревнования |
| **Управление заездами** | Подготовка списков участников, очереди заездов, запуск с телефона или ПК |

**В перспективе:** идентификация участников по **RFID**-меткам на финише — см. [rfid-transponders.md](rfid-transponders.md).

---

## 3. Состав (логический)

Система на площадке состоит из:

| Часть | Назначение |
|-------|------------|
| **Центральный блок** | Хранит протокол, показывает интерфейс, ведёт фото-финиш |
| **Стартовый модуль** | Отсчёт и сигнал старта у стартовой линии |
| **Финишный модуль** | Датчики пересечения линии по полосам |
| **Клиенты** | Смартфоны, планшеты, ноутбуки судей и секретарей |

Участникам и зрителям отдельное приложение не нужно — результаты видят судьи и организаторы; при необходимости протокол публикуется вручную.

---

## 4. Роли пользователей

| Роль | Кто | Основные действия |
|------|-----|-------------------|
| **Администратор** | Технический судья | Настройка системы, WiFi, параметры площадки |
| **Секретарь** | Секретариат соревнований | Участники, заезды, импорт списков, экспорт протокола |
| **Стартер** | Судья на старте | Запуск заезда: подготовка → отсчёт → GO |
| **Судья на финише** | Главный / финишный судья | Спорные финиши, фото-финиш, правка результатов |
| **Наблюдатель** | Тренер, комментатор | Только просмотр live-таблицы и итогов |

Доступ по простому PIN (поле часто без интернета). Одновременно могут работать **несколько человек** с разных устройств.

## 5. Основные понятия

| Понятие | Что это |
|---------|---------|
| **Соревнование (Event)** | Один день или этап: название, дата, число полос |
| **Категория** | Группа по дистанции, возрасту, полу (например, «500 m, U14») |
| **Участник** | Спортсмен с **номером (bib)**, ФИО, клубом |
| **Заезд (Heat)** | Один заезд: кто стартует, на каких полосах, режим старта |
| **Результат** | Время, место; может быть предварительным или окончательным |

**Заезд (Heat)** — главная «задача» для системы на площадке: пока активен один heat, система фиксирует его старты и финиши.

---

## 6. Режимы старта

### 6.1. Масс-старт

- Все участники заезда стартуют **одновременно**.
- Один общий отсчёт **3–2–1–GO**.
- Одно время старта на весь заезд.
- Типично: спринт, масс-старт на несколько полос.

### 6.2. Масс-старт, когда забег **не** идёт и не заканчивается по полосам

Частый случай на роликах: на старте участники стоят **сеткой** (условные полосы), после GO **смешиваются** на дистанции и финишируют **пелотоном** — кто в какой «дорожке» на линии, заранее неизвестно.

| Этап | Что фиксирует система | Что это значит на площадке |
|------|----------------------|----------------------------|
| **Старт** | Одно событие старта на весь heat | Общий GO, **одно время старта** для всех — режим `mass` **не меняется** |
| **Финиш (ИК)** | Отдельное срабатывание на каждый **сектор линии** (2–4 луча) | Поле «полоса» в системе = **место пересечения линии** (луч 1…4), а не «участник стартовал с полосы 2» |
| **Время** | Для каждого финиша: `время = t_финиша − t_старта` | Время **корректно**, если правильно **привязан участник (bib)** к этому финишу |
| **Кто финишировал** | В MVP — **не автоматически** из полосы старта | Нужна привязка bib к каждому финишу (см. ниже) |

```text
  СТАРТ (один GO, одно t_start для всех)
        │
        ▼
  … дистанция, полосы не соблюдаются …
        │
        ▼
  ФИНИШ: линия с 2–4 ИК-лучами
        │     │     │
     FINISH FINISH FINISH   ← «полоса» = какой луч, не номер на спине
     lane=2  lane=1  lane=4
```

#### Как вести heat в интерфейсе

1. **Секретарь** создаёт heat в режиме **масс-старт**, вносит **всех участников** heat (bib, ФИО).
2. **Полосы на старте** (если есть сетка) — **справочно** для стартера («кто где стоит»), не как жёсткая привязка финиша.
3. **Стартер:** Activate → Arm → GO — как обычный масс-старт.
4. После финишей в live-таблице появляются строки: **время + сектор линии**; bib может быть пустым или предварительным.

#### Как получить протокол (MVP)

| Способ | Кто | Когда использовать |
|--------|-----|-------------------|
| **Фото-финиш** | Судья на финише | Плотный финиш, несколько человек почти одновременно — **основной** способ расставить места и назначить bib |
| **Ручная правка** | Секретарь / судья | В протоколе: к каждому времени финиша привязать bib и место |
| **Порядок финишей** | Судья | Если финиши разнесены по времени (> 0,3–0,5 с), можно вручную сопоставить bib по очереди пересечений (ненадёжно при плотной группе) |
| **RFID** (позже) | Система | Метка на шлеме/номере → автоматический bib на финише; полосу по-прежнему даёт ИК |

#### Роли в таком заезде

| Роль | Действие |
|------|----------|
| **Стартер** | Только старт; полосы на финише не контролирует |
| **Судья на финише** | Фото-финиш + подтверждение «кто какой FINISH»; при споре — кадры |
| **Секретарь** | Закрывает heat после правок; экспорт с итоговыми bib и местами |

#### Чего система **не обещает** в MVP без RFID

- Автоматически понять, что участник №12, стартовавший с «полосы 3», финишировал в «полосе 1».
- Различить двух человек, пересёкших линию в **одном** секторе почти одновременно — только фото-финиш или RFID.

#### Когда полосы на финише всё же работают «как в документе»

- Дисциплина дистанции: спринт, каждый держит свою дорожку до линии.
- Секретарь назначает bib на полосы 1…4, финишы приходят **в те же** полосы — система может заполнить протокол **без** правок.

Технические детали: [TZ.md](TZ.md) (события `START` / `FINISH`), [rfid-transponders.md](rfid-transponders.md) (идентификация на финише).

### 6.3. Старт по одному

- Участники стартуют **по очереди**.
- У каждого **свой** отсчёт и **свой** момент старта.
- Перед стартом выбирается номер участника.
- Типично: квалификация, time trial.

### 6.4. Безопасный запуск

Старт двухэтапный:

1. **Подготовка (Arm)** — система готова к отсчёту.
2. **GO** — запуск отсчёта.

Так снижается риск случайного старта. То же самое доступно **кнопками на стартовом модуле** и **с телефона** — состояние синхронизируется.

---

## 7. Финиш и время

- На финишной линии — **2–4 сектора** (ИК-луча); в интерфейсе они называются «полосами».
- Пересечение фиксируется **автоматически** по каждому сектору **независимо**.
- При **масс-старте без дисциплины полос** сектор финиша ≠ стартовая полоса участника — см. [§6.2](#62-масс-старт-когда-забег-не-идёт-и-не-заканчивается-по-полосам).
- Система считает **время заезда** (финиш минус общий старт в режиме `mass`).
- Результат попадает в **live-таблицу**; итоговый **bib и место** могут потребовать действий судьи.

---

## 8. Фото-финиш

Если два или более участника финишируют почти одновременно:

1. Система **автоматически сохраняет** видеофрагмент финиша.
2. Судья открывает **фото-финиш** в том же интерфейсе.
3. Листает кадры и определяет, **кто пересёк линию первым**.
4. Подтверждает окончательный результат.

Фото-финиш — **инструмент судьи**, а не замена автоматической фиксации; при согласии датчиков и кадров результат принимается автоматически.

---

## 9. Управление с телефона и компьютера

### С компьютера (удобнее до и после соревнований)

- Создание соревнования и категорий.
- Импорт списка участников из таблицы (CSV).
- Редактор заездов: полосы, участники, режим старта.
- Полный протокол, правки, экспорт.
- Разбор фото-финиша на большом экране.

### Со смартфона (удобнее на площадке)

- Очередь заездов и активация следующего heat.
- Запуск старта: Arm / GO / отмена.
- Live-таблица результатов.
- Быстрое добавление участника и номера.
- Просмотр фото-финиша при споре.

**Один интерфейс** — разные экраны под размер устройства. Интернет не требуется: ноутбук и телефоны подключаются к **локальной сети** системы на площадке.

---

## 10. Типовой день соревнований

### Подготовка (за 1–2 часа до старта)

1. Включение системы на финишной линии.
2. Секретарь с ноутбука: импорт участников, формирование заездов.
3. Проверка: стартовый и финишный модули на связи, камера работает.
4. Стартер и судья подключают телефоны к локальной сети.

### Проведение заезда

1. Секретарь готовит heat в очереди.
2. Стартер **активирует** заезд и при необходимости назначает участников на полосы.
3. Стартер: **Arm** → **GO** → участники стартуют.
4. По финишам система показывает время в live-таблице.
5. При спорном финише судья открывает фото-финиш и фиксирует места.
6. Секретарь **закрывает** заезд; результаты сохраняются в протоколе.

### Завершение

- Экспорт протокола (таблица для публикации или архива).
- При необходимости — правки по решению судейской коллегии.

## 11. Сценарии использования

### Масс-старт на 4 полосы (дисциплина дорожек)

Четверо участников на старте → общий GO → каждый финиширует в своей дорожке → система связывает полосу с bib → таблица с местами и временем **без правок**.

### Масс-старт, финиш пелотоном

Десять участников, общий GO → на финише группа пересекает линию в разных секторах → live показывает **времена и сектора** → судья по **фото-финишу** (и при необходимости правкам) назначает bib и места → секретарь закрывает heat.

### Квалификация «по одному»

Участник №12 → индивидуальный старт → финиш → время в протокол. Затем №34, №56 и т.д.

### Спорный финиш

Два участника финишируют с разницей менее доли секунды → судья смотрит кадры → назначает места → результат помечается как подтверждённый по фото-финишу.

### Работа без интернета

Вся система работает автonomно на площадке. Данные хранятся локально; после соревнования протокол можно скопировать на флешку или ноутбук.

## 14. Критерии успеха для организатора

После внедрения система считается успешной, если:

- [ ] Секретарь готовит заезды с ноутбука без бумажных списков.
- [ ] Стартер запускает заезды с телефона или кнопок без сбоев.
- [ ] Live-результаты видны сразу после финиша.
- [ ] Спорный финиш разбирается по кадрам за минуты, не часы.
- [ ] Протокол экспортируется после блока заездов.
- [ ] Система работает весь день **без интернета**.
